      接入真实数据：24 小时采集服务 + 异常告警推送

      方式一：放一个数据文件（最快）

      把作品明细导出成 data/works.json，与 index.html 一起部署到任意静态服务器（Nginx、对象存储、GitHub Pages 均可）。页面打开时自动加载，右上角数据源会显示 data/works.json，示例见 data/works.example.json。

      方式二：手动导入（无需服务器）

      用右上角「载入数据」选择 CSV 或 JSON 文件即可，纯本地解析，数据不会上传。列名与下方字段表一致，也兼容中文表头。

      方式三：启动自带采集服务（推荐，真正 24 小时）

      本目录里的 realtime 就是一个完整的采集服务：定时拉数据 → 写入数据库 → 通过 SSE 实时推给本页面。Windows 双击 realtime\start.bat，或执行 node realtime/server.js；服务跑起来后本页会自动切成实时模式（右上角数据源变成「实时接口」，右下角出现采集状态和下次采集倒计时），数据一变页面就刷新，不用手动点。

      数据源在 realtime\config.json 里配置，支持三种：官方开放平台（抖音/快手等，需要企业资质与授权）、第三方数据服务商接口（飞瓜、蝉妈妈、新榜等）、以及自己的采集脚本 POST /api/ingest 推送。异常会自动推送到企业微信/钉钉/飞书群，配置 notify.webhook 即可。

      还没有任何密钥？执行 realtime\start.bat bilibili 就能直接接入 B站公开接口（热门视频 + 全站排行 + 最新投稿，约 400 条真实作品，免资质免密钥），先用真实数据把整套监控跑起来。接口字段映射写在 realtime\config.bilibili.json 的 map 里，照着改就能接你自己的接口。

      想在 GitHub 上挂着（不用开机）？把整个目录推到 GitHub，仓库里已经带了 .github/workflows/collect.yml：Actions 每 30 分钟自动采集一次并提交数据，Pages 直接展示这个页面。只要在仓库 Settings 里打开 Actions 写权限、启用 Pages 就行，详细步骤见 README 的「GitHub 部署」。

      三个平台现在采到什么：抖音热榜、快手热榜走官方公开接口（词条 + 热度值，免密钥），在「平台热榜」板块看排名变化和热度增速；B站走公开接口拿的是作品级真实数据（标题 / UP主 / 播放 / 点赞 / 评论 / 收藏），对标账号、赛道、人群需求三个板块都基于它计算。抖音、快手的作品级数据需要开放平台授权，拿到密钥后照着 map 填进配置即可并入总览和赛道板块。

      字段说明

      title作品标题或文案
      tags标签，JSON 数组或逗号分隔字符串
      publish_time2026-10-03 12:30:00 或 ISO 时间
      views / likes / comments播放量、点赞、评论

      统计口径

      • 互动率 =（点赞 + 评论 + 分享 + 收藏）÷ 播放量
      • 趋势图按作品发布小时聚合，同一小时的数据会随采集不断累加
      • 预警中的「较昨日同期」需要存在前一天数据；只有一天时仅保留爆款与低效作品类预警
      • 时间以浏览器本地时区为准，导入数据请保持同一时区
